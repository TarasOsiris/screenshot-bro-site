# Update Docs (text only)

Two pages, both mirrors of files in the app repo (`../screenshot-mac`,
`/Users/taras/repo/experiments/screenshot-mac`):

| Site | Mirrors (in the app repo) |
|---|---|
| `app/routes/docs.help.tsx` — `SECTIONS` (blocks) + the shortcuts tables | `screenshot/Code/Views/Help/HelpSection+Content.swift` and `ShortcutsContent.swift` |
| `public/project-schema.json` + the top-level field table in `app/routes/docs.project-schema.tsx` | `tools/project-schema.json` (generated by the app's `gen-project-schema` skill) |

"Text only" means block text, subtitles, captions, and shortcut rows. Don't recapture or add
images in `public/docs-help/`, and don't change layout or components. The page content is
English-only: locale-prefixed URLs render the same English text.

## 1. Pick the source ref, never the working tree

The app repo often has uncommitted work from another session, and its Help file can hold
lines for features that haven't shipped. **Always read from the latest ship tag:**

```bash
cd ../screenshot-mac
git status --short | grep -i 'Help\|project-schema'     # WIP here is NOT a source
git for-each-ref --sort=creatordate --format='%(refname:short)' refs/tags | tail -1   # e.g. v4.16-138
git log --format='%h %ad %s' --date=short <last docs sync date>..<tag> -- screenshot/Code/Views/Help tools/project-schema.json
```

Find the last docs sync with `git log --oneline -- app/routes/docs.help.tsx` in this repo.

## 2. Diff section by section

```bash
python3 .claude/skills/update-docs/helpdiff.py <tag>               # all sections
python3 .claude/skills/update-docs/helpdiff.py <tag> rows shapes   # just some
git -C ../screenshot-mac show <tag>:screenshot/Code/Views/Help/ShortcutsContent.swift   # compare tables by eye
```

`-` is the site and `+` is the app. Blocks map as `.heading→h`, `.paragraph→p`, `.bullet→li`
(numbered `"1. …"` bullets become `oli`), `.tip→tip`.

## 3. Port the changes and keep the site's own wording

Port new and changed app lines: new features, renamed controls, new headings, corrected
behavior. A small Python script that replaces exact block lines (asserting each old line occurs
once) handles 50+ edits more safely than one edit call per line. Keep the `{ kind: "li", text: "…" },`
formatting and escape `"` as `\"`.

**Keep these deliberate site differences. They are not drift:**
- Links the app can't have: the tutorial paragraph in Welcome, the Project File Schema link,
  the MCP guide paragraph in Automation, the Discord paragraph and site structure in Support.
- Verified numbers the app Help leaves out: **81** built-in language presets and **16** gradient
  presets. Re-verify them against the app source if a release touched locales or presets.
- "store uploads" in the free tier (upload isn't paywalled), "Apple Account" (not Apple ID),
  "purchase" (not only subscription), the Keychain note, and SVG "bundled presets".
- Platform wording: the product is Mac, iPad, **and iPhone**. Never write "Mac and iPad".
- Cross-references say "section" (the web page), where the app says "topic".
- Web-reader rewrites the site already chose over the app's wording (for example the Free-tier
  row tip and the merged pan and zoom bullets). Don't revert them to the app's phrasing.

**Leave out of the site:**
- Implementation detail (`NSFileCoordinator`, `NSMetadataQuery`), "now"-style release phrasing
  ("it now says so" becomes "it says so"), and lines that repeat another section.
- Anything that exists only in uncommitted WIP (step 1).

**Don't trust app Help labels blindly.** It drifts from the UI too. Check every control name
you port against the source at the tag:

```bash
git -C ../screenshot-mac grep -n -F '"<Label>"' <tag> -- 'screenshot/Code/*.swift' | grep -v /Help/
```

Known cases (the app Help still has the first two wrong; the site has them fixed):
- "Add Row" is really an unlabeled dashed **+** tile with the tooltip **Add new row**.
- "Add Template" is really a dashed **+** at the row's end with the tooltip **Add screenshot**.
- The template **⋯** menu's tooltip and label is **More actions**.
- "Spanning background" is really **Stretch across all screenshots**.

**Check version numbers against the tags.** The app Help said the project name field arrived
"before 4.10", but it shipped in 4.9 on Mac (iOS skipped 4.9). Use
`git tag --contains <sha> --sort=creatordate | head -1` and
`asc versions list --app 6760177675 --platform MAC_OS|IOS`.

If the tag is newer than the version live on the App Store, the docs will describe features
users can't get yet (for example the iPhone 18 / Duo frames in 4.15). Say so in the report.

## 4. Sync the schema

```bash
git -C ../screenshot-mac show <tag>:tools/project-schema.json > "$TMPDIR/schema.json"
python3 - "$TMPDIR/schema.json" <<'EOF'
import json, sys
site = json.load(open('public/project-schema.json'))
app = json.load(open(sys.argv[1]))
app['$id'] = site['$id']          # the app's $id points at an old host; keep the site's
open('public/project-schema.json', 'w').write(json.dumps(app, indent=2, ensure_ascii=False) + '\n')
EOF
git diff --stat -- public/project-schema.json
```

That formatting reproduces the committed file exactly, so the diff shows only real schema changes.
If top-level `properties` changed, update the "File structure overview" table and its field count
in `docs.project-schema.tsx`.

## 5. Verify

```bash
python3 .claude/skills/update-docs/helpdiff.py <tag>     # only the deliberate differences left
npm run typecheck && npm run build
PORT=3187 npx react-router-serve build/server/index.js &
for u in /docs/help /docs/project-schema /project-schema.json /es/docs/help; do
  curl -s -o /dev/null -w "%{http_code} $u\n" http://localhost:3187$u; done
curl -s http://localhost:3187/docs/help -o "$TMPDIR/help.html"
grep -c '<a new label you ported>' "$TMPDIR/help.html"   # new strings present, old labels gone
kill %1
```

Write the page to a file before grepping. Piping through `sed` or `grep -o` with `…`/`▸` characters has
silently matched nothing before. If a port answers with stale content, another server is still
bound to it, so use a different port.

## 6. Commit and push

Straight to `main` (the site deploys from it):

```bash
git add app/routes/docs.help.tsx app/routes/docs.project-schema.tsx public/project-schema.json
git commit -m "Sync the docs with the app's Help as of <tag>"
git push
```

In the body, name the tag, the label fixes, and anything described that isn't live yet.
